Sources and licensing

This page records the API references and licenses used by Project Requiem 0.3.0-pre.5. A matching API signature establishes compatibility with a captured method, not correct behavior in every native gameplay path.

Captured game metadata

Game-specific method signatures were checked against read-only reflection from the user's Resident Evil Requiem TDB83 installation, captured on 14 October 2026. The recorded framework build was dated 26 April 2026, with commit:

c4b1314820d20255febf7834903e8cedb669b49c

The installer retains the existing REFramework DLL. Reflection dumps and reference repositories are development inputs and do not ship in the ZIP. No fixed game memory offsets are used.

Official REFramework references

  • REFramework source provides the framework implementation.
  • The SDK API covers hooks, native fields, allocation and the primary camera. Temporary projectile rotation and One Life translation arguments use this API.
  • Hook-local storage isolates recursive and threaded hook calls.
  • Type reflection supports exact method signatures and inherited fields. Uncaptured request-direction fields and archive-state getters are accepted only after runtime name/type checks.
  • Application callbacks supply gameplay and render timing.
  • Quaternion documents the constructor order (w, x, y, z).
  • Managed objects, fields and arrays support the owned item-data codec used by One Life (Easy).
  • Draw provides the HUD, panic overlay and death-cache markers.
  • ImGui provides controls and font loading. Its combo binding returns a key from the Lua options table; the language list uses 1/2.
  • The combo implementation confirms table-key selection and the fallback to the first key for an unavailable selection.
  • JSON persistence documents configuration and ledger writes.

These references explain API contracts. Automated mocks based on them do not establish native UI, camera, inventory or save-flow verification.

Community API references

Namsku's RE Engine trainer

The trainer repository supplies additional references for infinity flags, rank factors, weapon data and native motion-layer speed. The RE9 implementation is in re9/requiem_trainer/features.lua.

RE9 Randomiser

KyroGeorge2's randomiser identifies healing item IDs and illustrates why general inventory merge hooks would also affect item-box transfers. Project Requiem limits scarcity to recognized world objects.

RELit

originalnicodr's RELit provides renderer enable/intensity API references. Project Requiem's current depleted-light path uses reversible enable/visibility flags and leaves intensity unchanged.

The Lua algorithms are written for this mod. Names, signatures and item IDs are used for API interaction; external repositories are not bundled.

Documentation style

The documentation follows the user-requested Markdown skill, version 1.2.1. The project lint configuration checks current English and Vietnamese documents with markdownlint. Archived release documentation retains its historical form.

Mod license and distribution

The MIT license covers Project Requiem code. The consolidated LICENSE.md also contains notices for the bundled font, separately supplied runtime, development tools and reference sources, with installed development package inventories.

Components retain their own licenses. Reference sources without a located license are identified explicitly. No Capcom executable, DLL or game assets are distributed.
